# Retry Effects only when safety is provable

Effects are classified as provably read-only, idempotent under a stable external key, or ambiguous and potentially destructive. The first two classes may retry within their policy using the original identity; the third never retries after an uncertain acknowledgement. Change-checkpoint creation, commit, push, and pull-request creation or update are separate durable Effects with stable identities and individually recorded outcomes. A later failure never rolls back an earlier success; the GUI shows the exact completed boundary and retries only the incomplete Effect after reconciliation, without duplicating a commit, push, or pull request. SSH commands and every Git or pull-request mutation reconcile observable state first, and when the result still cannot be established Jet reports Outcome unknown and requires a user-controlled decision.

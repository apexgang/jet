# Pair GUI clients directly with Planes

A controlling GUI client first selects or enters the reachable SSH or Tailscale SSH endpoint and user for a target Plane. Each installation generates an Ed25519 Client identity whose private key is stored only through platform credential storage and is never exportable through Jet's interfaces; Jet does not claim portable hardware-backed non-exportability. The target then issues either an eight-digit, numeric-only `xxxx-yyyy` manual pairing code or a versioned QR payload containing the endpoint and a cryptographically random 128-bit one-time token. The GUI submits it over the already authenticated SSH connection, both sides display an authentication string, and the user confirms the pending pairing on the target. The token expires after two minutes, is single-use, and five failed attempts invalidate it. A fresh challenge signed by the Client identity completes Pairing, with protocol and algorithm identifiers retained for migration. The short-lived token proves fresh intent while the installation's public key becomes the durable credential; secret and token comparisons are constant-time. That one pairing is a full-trust authorization for all current and future Jet-managed Projects and Workspaces on the Plane and, on desktop installations, for No-Visa tools; filesystem access remains bounded by the target user's OS permissions, sandbox, and approval policy, and locations outside registered Projects are not directly exposed. Jet does not require a second agent-access grant. Disabling or revoking a Paired client immediately rejects its new commands, closes its streams, and gracefully terminates its in-flight No-Visa operations before a bounded forced stop, but does not stop Visa Runs hosted by the target. Disable retains the public key; revoke deletes it. A Plane's Pairing gate controls only new clients, each GUI client keeps its own Plane registry, and Planes neither synchronize a fleet database nor communicate with one another. Pairing and its key inventory apply ASVS 6.3.1, 6.3.4, 6.7.2, 8.2.1, 8.2.2, 8.3.1, 8.3.2, 8.3.3, 11.1.1, 11.1.2, 11.2.1 through 11.2.5, 11.5.1, 11.6.1, 13.3.1, and 13.3.2.

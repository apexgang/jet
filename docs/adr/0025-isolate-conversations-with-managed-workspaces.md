# Isolate Conversations with managed Workspaces

Jet mirrors Codex Desktop's Git isolation: every managed v1 Run belongs to a registered Git Project, and multiple Conversations working there receive separate managed Workspaces under `~/.jet/workspaces`, implemented as Git worktrees initially detached from their selected starting branches and owned by their Conversations. Managed Workspaces are the default. A Project permits at most one active Jet-managed Run in its explicit non-isolated Local checkout; additional Runs must use Workspaces, scheduled use there defaults off and requires Project-level enablement, and Jet warns that unrelated external processes cannot be locked. When seeding a Workspace, the user selects no Local-checkout changes, all eligible changes, or individual paths. Jet first captures an immutable snapshot of tracked changes and selected non-ignored untracked files; ignored files require explicit selection, symbolic links are retained without following their targets, and submodules contribute only their Git-link commit. Application verifies the expected base and leaves the new Workspace unchanged on failure. Promotion back to a selected permanent checkout or branch first compares its current state with the Workspace's expected base, displays the proposed result, and uses a three-way Git application. It never overwrites conflicting work: conflicts remain isolated in the Workspace for the user to resolve, and Jet does not remove the Workspace until promotion succeeds and the resulting state is verified. Jet supports `.worktreeinclude`, keeps the latest 15 clean inactive unpinned Workspaces by default, and never automatically removes a running, scheduled, pinned, dirty, unpushed, conflicted, or unsuccessfully promoted Workspace. `jetd` owns diffs, staging, snapshots, restoration, cleanup, and promotion to a permanent Project checkout.

# Use native and equivalent automatic reviewers

Jet's global-on-a-Plane Automatic review mode applies to every supported Harness while preserving each Harness's sandbox, filesystem, network, and permission boundaries. It reviews only actions that would otherwise require a person; allowed in-boundary work continues without review. A Craft uses its Harness's native separate reviewer when it satisfies the Jet contract, as Codex does, or provides Jet's versioned equivalent through the Run's own Provider and Account binding using that Provider's fastest suitable low-effort reviewer Model. Cross-Provider review requires explicit persistent permission; otherwise an unavailable reviewer falls back to the user, never another Provider. The reviewer receives a bounded visible transcript and exact requested action and returns risk, user-authorization assessment, decision, and rationale. Jet independently denies critical classes including credential probing, exfiltration, persistent security weakening, policy bypass, and materially destructive actions; low- and medium-risk requests may proceed under policy, while high-risk requests require sufficient explicit user authorization and no deny rule. Malformed results, timeouts, and internal failures fail closed. A denial forbids equivalent workarounds, three consecutive denials or ten within the last fifty reviews stop further review attempts for that turn, and a user override authorizes only one retry of the exact action while still allowing the reviewer to deny it. A GUI may apply the same setting to several connected Planes, but every Plane commits and reports its result independently. The trusted-core decision point and recorded review outcomes implement ASVS 8.3.1, 8.3.2, 8.3.3, 16.2.1, 16.3.2, 16.3.3, and 16.3.4.

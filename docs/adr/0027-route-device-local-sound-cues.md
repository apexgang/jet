# Route device-local sound cues

Jet emits deduplicated semantic Sound cues for attention and completion rather than storing or transmitting arbitrary audio as part of a Run. Each device owns its Sound profile, copies imported sounds into local Jet storage, and may map a cue to local playback or to another Plane currently reachable through the controlling GUI client. Desktop `jetd` can play without an open GUI in a logged-in session; mobile playback is only guaranteed while the v1 app is active. Cross-Plane routing is best effort because Planes do not communicate directly. If a selected custom sound cannot be decoded or played, Jet uses that playback device's default OS notification sound; if the remote playback target is unreachable, the controlling device uses its default OS notification sound. Disabled sound effects remain silent, Event-journal replay never replays a cue, and visual notifications are configured independently.

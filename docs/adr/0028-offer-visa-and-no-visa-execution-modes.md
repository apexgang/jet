# Offer Visa and No-Visa execution modes

Every Conversation selects one of two explicit execution modes, defaulting to Visa. In Visa mode, the Harness, Jet Craft, and `jetfueld` run on the destination Plane, preserving exact Harness-native behavior. In No-Visa mode, they remain on the Home Plane and the Home `jetd` owns direct SSH connections to one or more paired destination Planes; SSH authenticates through the user's configured transport credentials, then Jet authenticates the paired desktop installation with its Client identity from platform credential storage. The GUI is not a relay, and mobile cannot start No-Visa work. Each remote request carries both the paired installation identity and the originating Actor, and the destination `jetd` reauthorizes it while enforcing Workspace scope, operating-system permissions, approvals, and audit records. Disabling or revoking the pairing immediately stops admission of new remote work. Each tool call identifies its Plane and Workspace. Process execution uses an argument array, a Workspace-relative working directory, and explicit environment changes; shell syntax is a distinct, visibly labelled operation that receives its own approval review. Raw commands, absolute working directories, path traversal, and SSH-shell interpolation are rejected. The GUI groups files, terminals, and diffs the same way in either mode. Jet provides no cross-Plane transaction: loss of one destination fails only its affected operation, and only provably read-only operations may be retried automatically. Jet will maximize shared GUI and Git behavior across both modes but will describe known gaps honestly: No-Visa mode cannot guarantee native remote checkpoints, tool discovery, extensions, or sandbox internals. Switching modes or origin/destination Planes starts a new Run; Jet resumes a native Harness conversation already present there or starts one from a provenance-marked context package, without copying credentials or opaque native session files. Trusted-boundary validation, installation identity, and originating-Actor authorization apply ASVS 1.2.5, 2.2.1, 2.2.2, 8.2.1, 8.2.2, 8.3.1, 8.3.2, 8.3.3, 13.2.2, and 13.2.6.

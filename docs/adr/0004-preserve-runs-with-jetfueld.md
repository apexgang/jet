# Preserve active executions with jetfueld

Each active Run and each open Workspace terminal has a lightweight `jetfueld` helper in the corresponding execution role. A Run-role helper retains up to 64 MiB of native Harness input on disk until `jetd` durably acknowledges its source offset through the Craft; at the limit it applies backpressure rather than discarding potentially semantic input. A terminal-role helper uses a rolling eight-MiB spool and records an explicit gap when old bytes are displaced. Atomic, non-secret descriptors in owner-only `~/.jet/runtime` identify each helper's role, execution, process start identity, socket, executable version, and replay position. After restart, `jetd` validates ownership and authoritative SQLite state before adoption; an unmatched live helper becomes an Orphaned execution. Only an interactive user may inspect its read-only metadata or request adoption or termination. Adoption additionally requires the helper identity, registered Project, and canonical Workspace root to validate; otherwise Jet can only leave it running or terminate it. A descriptor is removed as stale only after proving its process is gone. No helper exists when no Run or terminal needs preservation. GUI disconnection never affects an execution. After an operating-system reboot, Jet marks a previously active Run `lost`, preserves its Conversation and Workspace, and requires explicit Resume into a new Run; only an independently authorized Scheduled task or Auto-continue policy may start later work automatically. A former terminal is reported closed rather than falsely preserved.

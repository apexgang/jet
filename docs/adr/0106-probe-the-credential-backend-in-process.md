# Probe the credential backend in process

`jetd` observes the platform credential store by speaking to it through its own interface, in process: the freedesktop Secret Service over the session bus through `zbus`, and the macOS Keychain through the Security framework. It does not infer the store from a package, a socket path, or the operating system, and it does not delegate the observation to a command-line tool a Plane may lack. The probe never prompts and never starts anything: Secret Service calls carry `NoAutoStart` and answer no Prompt, so a store that is not running is reported as unavailable and a locked collection as locked; Keychain calls run with user interaction disabled, so a locked keychain is read from the refusal instead of from a dialog. Observation is read-only and happens with every Capability snapshot and revalidation; the create/read/delete round trip ADR-0076 requires before durable Pairing is a separate verification, run only when a client asks, that leaves no item behind. Both crates are platform-scoped dependencies of `jet-core` and neither prompts on its own.

# Package and update jetd per user

Exactly one installation channel owns the core payload and service on a desktop. A GUI-managed installation stages immutable versions under `~/.jet/core/versions` and uses the GUI updater: macOS uses a notarized Developer ID distribution and `SMAppService` LaunchAgent, while Linux uses a systemd user service with XDG autostart fallback. A Homebrew-managed installation lives in Homebrew's versioned prefix, declares required external command-line tools as formula dependencies, runs through [`brew services`](https://docs.brew.sh/Manpage#services-subcommand), and disables Jet's self-updater. The GUI detects and controls a compatible externally managed daemon but never overwrites it; core executables never invoke a package manager. Changing channels is an explicit user operation: Jet drains the old daemon, validates the signed replacement and its protocol and schema compatibility, preserves `~/.jet` state and running helpers, and activates the replacement only after the former service has relinquished its lifetime lock; installing or removing the package remains a package-manager action. Updates atomically switch versions and restart only `jetd`; separately supervised `jetfueld` processes keep Runs alive, retain their executable version until exit, and must survive tested update, channel-change, and rollback flows without event gaps.

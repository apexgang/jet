# Distinguish forgetting from deletion

Forgetting removes Jet-owned conversation metadata, presentation data, names, and artifacts while leaving harness-native history intact. Deleting everywhere additionally stops an active run after confirmation and requests native deletion when supported; autodelete rules target inactive data and may delete native history only through a separate explicit authorization. Project unregistration likewise removes only Jet's registration. Project removal is a separate two-phase operation exposed only to interactive GUI clients: `jetd` first returns the canonical path, disk usage, active Runs, schedules, dirty files, unpushed commits, and associated Workspaces, then requires typed Project-name confirmation bound to that preview. It rejects filesystem roots, the user's home, `~/.jet`, paths containing another registered Project, and Projects with active Runs or schedules. It uses recoverable system Trash where available; otherwise permanent deletion needs a second confirmation. The removal command is absent from Harness and Jet Craft surfaces, schedules, and automatic rules.

# Select Utility work through a Plane binding

Each Plane has one Plane-wide Utility Account binding. Its Jet Craft identifies the Provider's smallest currently suitable Model at minimum reasoning effort, and every Utility-model result records the exact Provider, Account binding, Model, purpose, and policy used. Jet never silently substitutes another Provider, binding, or Plane. Each purpose is independently disableable. Naming receives only bounded title and opening context, Git text receives only necessary Change-checkpoint material, and Autodelete compilation receives only its rule prompt; credentials, diagnostics, and raw terminal output are never included. Sending Conversation or diff content to a Provider different from the originating Conversation requires persistent disclosure and explicit enablement. Utility jobs have no tools or filesystem or network authority beyond their single inference request. Outputs are untrusted data subject to allowlisted schemas, size limits, and trusted-core validation and can never become Commands. Automatic naming and Git text use deterministic fallbacks when Utility work is unavailable, while natural-language Autodelete compilation fails closed and authorizes no deletion. These controls apply ASVS 1.5.2, 2.2.1, 2.2.2, 8.3.1, and 14.2.3.
